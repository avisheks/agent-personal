# Is On-Policy Synonymous with Model-Free, and Off-Policy with Model-Based?

## Short Answer

**No.** These are two independent (orthogonal) classification axes. Conflating them is a common misconception because the most famous algorithms happen to cluster: PPO (on-policy, model-free) and MuZero (off-policy, model-based). But all four quadrants are populated.

## The Two Axes

### Axis 1: On-Policy vs Off-Policy

This describes **whose data you learn from**:

- **On-policy:** Learn only from data generated by the *current* policy. After each policy update, old data is discarded. (PPO, A2C, REINFORCE, GRPO)
- **Off-policy:** Learn from data generated by *any* policy (including old versions, other agents, or human demonstrations). Data is stored in a replay buffer. (DQN, SAC, TD3, CQL)

### Axis 2: Model-Free vs Model-Based

This describes **whether you learn environment dynamics**:

- **Model-free:** Learn a policy or value function directly from (state, action, reward) tuples. No internal model of "what happens next." (PPO, DQN, SAC, REINFORCE, GRPO)
- **Model-based:** Learn (or are given) a dynamics model `P(s'|s,a)` and use it for planning — simulating trajectories mentally before acting. (MuZero, DreamerV3, AlphaZero, MBPO)

## The 2×2 Matrix: All Four Combinations Exist

| | Model-Free | Model-Based |
|---|-----------|-------------|
| **On-Policy** | PPO, A2C, REINFORCE, GRPO, TRPO | Dyna (on-policy variant), MBPO (borderline — generates on-policy synthetic data from learned model) |
| **Off-Policy** | DQN, SAC, TD3, CQL, IQL | MuZero, DreamerV3, AlphaZero, World Models (Ha & Schmidhuber 2018) |

### Examples of Each Quadrant

1. **On-policy + Model-free (most common in LLM RL):** PPO, GRPO. Generate data from current policy → compute advantages → update → throw away data. No dynamics model.

2. **Off-policy + Model-free:** DQN, SAC. Store all experience in replay buffer → sample old transitions → update Q-function. No dynamics model, but reuse old data.

3. **Off-policy + Model-based:** MuZero, DreamerV3. Learn a dynamics model from replay buffer → plan by "imagining" future states in the learned model → act from the plan.

4. **On-policy + Model-based:** Less common but exists. Dyna-style algorithms that generate synthetic rollouts from a learned model but only use them within the current policy iteration. MBPO (Model-Based Policy Optimization) sits here — it uses the learned model to generate synthetic on-policy data for the current policy.

## Why the Confusion Arises

The confusion comes from correlated practical properties:

- **On-policy methods are sample-inefficient** (throw away data after each update) → people associate them with "simple" → model-free
- **Model-based methods are sample-efficient** (plan in imagination) → people associate them with "reusing data" → off-policy
- **In LLM RL specifically**, PPO/GRPO (on-policy, model-free) dominate, and world models are barely explored — so practitioners only encounter one quadrant

But these are engineering correlations, not logical necessities. A model-based method CAN be on-policy (generate imagined rollouts from current policy only). A model-free method CAN be off-policy (DQN stores and replays old transitions).

## For LLMs Specifically

| LLM RL Method | On/Off Policy | Model-Free/Based | Notes |
|---------------|--------------|-----------------|-------|
| PPO (InstructGPT) | On-policy | Model-free | Generates from current policy, discards after update |
| GRPO (DeepSeek-R1) | On-policy | Model-free | Same as PPO but with group baseline instead of critic |
| DPO | Off-policy (static dataset) | Model-free | Trains on fixed preference pairs — never generates |
| Expert Iteration | On-policy | Model-based (implicit) | Uses search/planning to generate improved targets |
| MCTS + LLM (RAP) | On-policy | Model-based | LLM is both policy AND world model for planning |

DPO is interesting — it's technically off-policy (learning from data generated by a different policy, the SFT model) and model-free. This shows that even in LLM RL, the two axes are independent.

## Key Takeaway

Think of RL algorithms as having two independent toggle switches:
- **Data reuse:** On-policy (fresh data only) vs Off-policy (replay old data) — affects sample efficiency
- **World knowledge:** Model-free (trial and error) vs Model-based (plan ahead) — affects planning capability

These switches are independent. Flipping one doesn't require flipping the other.
